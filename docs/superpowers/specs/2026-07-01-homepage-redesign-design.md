# moin 홈페이지 & 사용자 동선 리디자인 설계

- 작성일: 2026-07-01
- 상태: 설계(스펙) — 사용자 검토 대기
- 기준 시안: `mockups/ia-sections.html` (+ `mockups/minimal-colors.html`의 "잉크/무채색")

## 1. 개요 / 목표

현재 공개 사이트는 따뜻한 에디토리얼(크림/그린) 톤으로 완성도는 있으나, 색·타이포·정보구조가 사용자가 원하는 방향과 맞지 않고 "데모 티"(과거 날짜 하드코딩, 더미 후기, "데모" 문구, 외부 핫링크 이미지)가 남아 실결제 서비스로서 신뢰도를 떨어뜨린다.

목표: 공개 사용자 동선을 **미니멀 / 화이트 · 잉크·무채색 · 정리된 섹션 구조(구조 B)**로 리디자인하고, 같은 작업에서 데모 흔적을 정리한다.

## 2. 확정된 디자인 방향

- **무드:** 차분한 미니멀 / 화이트. 색은 모임 사진이 담당.
- **포인트 컬러:** 잉크·무채색 — 블랙(#111) 단일 포인트.
- **정보 구조:** 구조 B(정리된 섹션형) — 히어로 → 모임 그리드 → 오픈예정 레일 → 여는이 CTA → 후기 → 푸터.
- 시각적 기준은 위 목업 파일. 본 스펙은 그 목업을 실제 코드베이스에 이식하는 설계다.

## 3. 디자인 토큰 (styles.css `:root` 교체)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | #ffffff | 페이지 배경 |
| `--bg-2` | #f6f7f9 | 카드 placeholder·보조 면 |
| `--ink` | #111111 (텍스트), #0e1116 헤드라인 | 본문·포인트 |
| `--muted` | #6b7280 | 보조 텍스트 |
| `--line` | #ececf0 | 보더·구분선 |
| `--accent` | #111111 | 버튼·칩 on·강조(무채) |
| radius | 카드 18px, 버튼 999px, 입력 12px | |
| shadow | `0 18px 40px rgba(15,17,22,.08)` (hover) | |
| 타이포 | Pretendard/Noto Sans KR, 300–900. 헤드라인 `word-break: keep-all` | |

기존 웜 토큰(--paper/--green/--coral/--yellow 등)과 그리드 배경 텍스처는 제거/대체.

## 4. 스코프

**포함 (옵션 1 — 사용자 동선 전체)**
- `index.html` 구조 + 스타일
- 공용 컴포넌트: 헤더, 푸터, 모임 카드, **상세 드로어, 결제 모달**
- `my-history.html`, `payment-result.html` 톤 정렬(2순위)
- 정책 페이지(terms/refund/privacy): 톤 미세 정렬

**제외**
- `admin.*` (내부용 — 별도/추후)
- 결제 로직·백엔드·엣지 함수 (시각 변경만)

## 5. 컴포넌트별 설계

- **헤더:** 스티키, 좌측 워드마크 `moin`, 중앙 슬림 내비(모임/오픈예정/여는이/후기), 우측 `내 신청`(ghost) + 주 CTA. 블러 배경.
- **히어로:** 텍스트 중심(이미지 카드 없음) — eyebrow + 큰 헤드라인 + 한 줄 설명 + 검색 인풋. 과거 날짜 하드코딩 카드 제거.
- **필터 칩:** 전체/정기/원데이/소모임/오픈예정. `on` = 블랙. 모임 그리드 상단.
- **모임 카드:** 이미지(16:10) + 메타(지역·일시) + 제목 + 가격/잔여석. 18px 라운드, hover 떠오름. 유형 배지(옵션).
- **모임 그리드 섹션 ("지금 참여할 수 있는 모임"):** 3열 반응형. 칩 필터로 정기/원데이/소모임 통합 노출 — **기존의 별도 이벤트·소모임 섹션은 이 그리드 필터로 흡수**.
- **오픈예정 레일:** 가로 스크롤 미니카드 + 신청률 바(`active/capacity`). 기존 waitlist 데이터 사용.
- **여는이 CTA 밴드:** 블랙 배경 카드, 흰 CTA. 기존 host 카피 유지.
- **후기:** 3열 카드. **더미 텍스트 대신** 실제 후기 연동(아래 6 참조) 또는 표기 정리.
- **푸터:** 사업자정보(상호/대표자/사업자번호/통신판매업/주소/고객센터) + 정책 링크(이용약관/취소·환불/개인정보) + 서비스 제공기간 안내를 **반드시 유지**(직전 작업물). 미니멀 톤으로 재배치.
- **상세 드로어 / 결제 모달:** 동일 토큰으로 재스타일. 결제창의 test/live/demo 분기 카피·로직은 **그대로 유지**(시각만 변경).
- **모바일:** 하단 탭은 새 IA에 맞게 정리(모임/오픈예정/내 신청 등) 또는 헤더 내 메뉴로 단순화. 그리드 1열.

## 6. 콘텐츠 / 데모 정리 (동시 반영)

- `index.html` meta description의 "데모" 제거.
- 후기 카운트 "데모 후기 3개" 및 더미 후기 → 실제 후기(가능하면 기존 큐레이션 후기 기능 연동) 또는 정적 표기 제거.
- 하드코딩 히어로 추천 카드(과거 날짜·"4자리") 제거 — 히어로는 텍스트형.
- Unsplash 핫링크: 운영 이미지로 교체하거나, 최소한 안정적 호스팅/지연 로딩 처리(별도 후속 가능, 스펙에 명시).

## 7. 구현 영향 (파일)

- `styles.css`: 토큰·공용 컴포넌트 스타일 대폭 개편(웜→잉크 미니멀). 가장 큰 작업.
- `index.html`: 섹션 구조 재구성(이벤트·소모임 별도 섹션 제거, 레일/후기/여는이 정돈). 내비·모바일 탭 링크 갱신.
- `main.js`: 카드/섹션 렌더링 조정 — 별도 이벤트·소모임 리스트(`data-event-list`, `data-small-group-list`) 제거하고 필터 그리드로 통합. 드로어/결제 마크업 클래스 정합.
- `public-meetup.js`: 카드 마크업 헬퍼(`createTagMarkup` 등) 새 구조 반영.
- `my-history.html`, `payment-result.html`: 톤 정렬.
- (선택) 정책 페이지 톤 미세 정렬.

## 8. 보존 불변식 (절대 깨지면 안 됨)

- **보안:** 모든 공개 렌더링의 escape/URL 검증 유지(`escapeHtml` 단일 모듈, `escapeAttribute`, `escapeImageUrl`). innerHTML에 미escape 사용자 입력 금지.
- **결제:** 결제창 test/live/demo 분기 카피·`isTossConfigured`/`isTossLiveMode` 로직, 금액 서버 고정, 이중결제 방지 — 시각 변경이 건드리지 않음.
- **푸터 계약:** 사업자정보·정책 링크·서비스 제공기간 안내·"데모" 문구 부재(직전 작업 + 테스트).
- **캐시버스팅:** 모든 모듈 import `?v=__ASSET_VERSION__` 유지, 신규 파일은 cp 목록·캐시버스트 목록에 추가.

## 9. 테스트 영향 & 전략 (TDD)

리디자인은 마크업/문구를 바꾸므로 `tests/paymentSecurity.test.js`의 일부 **소스 계약 핀**이 영향을 받는다. 구현 시 TDD로 핀을 새 마크업에 맞춰 갱신하되, **보안·결제·푸터 불변식 핀은 계속 통과**해야 한다.

영향 가능 핀(구현 중 확인·갱신):
- `createTagMarkup(...)` 정확 매칭
- 이미지/속성 escape 핀(`alt=`, `src=`, `data-detail=`)
- 결제 카피 핀(`public payment copy ...`, `checkout copy switches to a real-charge ...`) — 카피 유지 시 영향 적음
- 푸터 계약 핀(`site footer carries business registration info ...`) — 사업자정보·정책·서비스 제공기간·데모부재 유지
- `main.js delegates modal focus management ...`
- cacheBust/cp 목록 핀

전략: 변경되는 마크업의 핀을 먼저 새 기대값으로 수정(RED) → 구현(GREEN). 불변식 핀은 그대로 유지. 전 구간 `npm test` + `smoke:browser` 그린 유지.

## 10. 배포

- 신규 페이지 파일 없음(기존 파일 개편). 신규 JS 모듈이 생기면 워크플로우 cp 목록 + `cacheBustedSourceFiles`에 추가.
- main push → Pages 자동 배포. 배포 후 데스크톱/모바일 스크린샷으로 라이브 확인.

## 11. 범위 외 / 리스크

- admin 화면 톤 불일치는 이번 범위 밖(추후).
- 이미지 자산(소유 이미지) 확보는 콘텐츠 작업과 병행 — 미확보 시 placeholder/지연로딩으로 임시.
- 큰 CSS 개편이라 회귀 위험 → 컴포넌트 단위로 진행하고 각 단계 스크린샷 QA.

## 12. 완료 기준

- 공개 동선(홈·카드·드로어·결제·내 이력·결제결과)이 잉크 미니멀 톤으로 일관.
- 홈이 구조 B로 정돈(이벤트/소모임은 필터 그리드로 통합, 오픈예정 레일·여는이·후기 정돈).
- 데모 흔적(문구·하드코딩 카드·더미 후기) 제거.
- 푸터 사업자정보·정책·서비스 제공기간 유지.
- 보안·결제 불변식 유지, 전체 테스트 + 브라우저 스모크 그린, 라이브 검증.
